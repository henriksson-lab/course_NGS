# Sequencing instruments and chemistry: concept list for an NGS library-prep course

Format per concept: **Concept** - what it is. *Why it matters:* consequence for library design/prep. *Repo:* example protocols in /home/mahogny/github/chem that depend on it (directory names, abbreviated). Items marked [KB] come from general knowledge, not from the repo; repo coverage of Element, Ultima, and Singular is thin (see section I).

Core idea for students: a library is a molecule built so that (1) it can be captured on a surface or loaded into a pore/ZMW, (2) a primer or motor can start on it, (3) the right bases land in the right read, (4) its identity (sample, cell, molecule) is readable, and (5) it has a size and base composition the instrument tolerates.

---

## A. Illumina: surface, clustering, chemistry

1. **Flow cell lawn oligos P5 and P7** - two oligo types covalently grafted to the flow cell (P5 29 nt, P7 24 nt in lib/illumina.py). Library ends carry the matching sequences. Illumina's own adapter document never uses the names "P5/P7"; they are community names. *Why:* a fragment needs one P5 end and one P7 end to cluster; the "flow-cell-binding" part of every adapter is non-negotiable. *Repo:* lib/illumina.py; every Illumina-compatible protocol.
2. **Only P5/P7 heteroduplex molecules form clusters** - molecules with the same flow-cell arm at both ends (or with zero or one adapter) cannot bridge. *Why:* explains why Tn5 with two adaptors yields only 50% usable product, why one-adapter ligation products are harmless to clustering, and why qPCR (adapter-specific) rather than Qubit is needed to load PCR-free libraries. *Repo:* lib/nextera.py (TAGMENTATION_OUTCOMES, amplifiable()); nextera-xt-dna-library-prep; truseq-dna-pcr-free ("non-qPCR methods quantify molecules that do not have adapters on both ends and do not form clusters"); truseq-stranded-mrna (zero- and one-adapter fragments).
3. **Bridge amplification (random flow cells) vs ExAmp on patterned nanowells** - older MiSeq/HiSeq 2500/NextSeq 500 flow cells give clusters at random positions via bridge PCR; HiSeq 3000/4000/X, NovaSeq, NextSeq 1000/2000, iSeq use ordered nanowells seeded by one molecule each and amplified isothermally (ExAmp, recombinase-driven, kinetic exclusion) [KB]. *Why:* affects cluster-calling needs (see low diversity), duplicate types (optical vs clustering duplicates), index hopping risk, and size bias (ExAmp favours short fragments). *Repo:* instrument names recur in notes (MiSeq, HiSeq 3000, NovaSeq, NextSeq 500); no dedicated mechanism note.
4. **Cluster density and loading concentration** - too many clusters per tile merge and fail chastity/purity filters, too few waste capacity; loading is titrated per instrument. Patterned flow cells are less forgiving of overloading in a different way (more empty or dual-occupied wells). *Why:* pool concentration must be quantified by a method that counts only adapter-bearing, amplifiable molecules (qPCR/KAPA, or fragment-size-aware fluorometry). *Repo:* illumina-16s; truseq-dna-pcr-free; several notes describe "underclustered MiSeq" runs and KAPA qPCR before loading.
5. **Sequencing by synthesis (SBS) with reversible terminators** - each cycle incorporates one fluorescently labelled, 3'-blocked dNTP, images, then cleaves dye and block. One base per cluster per cycle. *Why:* defines read length as a cycle count; errors are mostly substitutions; the library supplies a primer-binding site and then every downstream base is read in order. *Repo:* universal assumption (all Illumina protocols).
6. **Four-, two-, and one-colour chemistries** - MiSeq/HiSeq: 4 dyes/channels. NextSeq/NovaSeq/NovaSeq X: 2 channels (G = no signal) [KB]. iSeq 100: 1 channel, 2 images [KB]. *Why:* in 2-colour chemistry "no signal" is read as G, so empty or dying clusters and cycles past the end of the molecule produce poly-G reads; index sets must stay colour-balanced at each cycle; poly-G trimming (fastp --trim_poly_g) is needed downstream. *Repo:* ~177 notes cite NextSeq/NovaSeq/iSeq; few mention poly-G explicitly.
7. **Read primers and the standard order of reads** - Read 1 primer, Index 1 (i7) primer, Index 2 (i5) primer, Read 2 primer; reads are done Read 1, Index 1, [turnaround], Index 2, Read 2. Sequences: lib/illumina.py (TRUSEQ_READ1, TRUSEQ_READ2, INDEX1_PRIMER, INDEX2_PRIMER_RC). TruSeq-style and Nextera-style (Tn5 mosaic-end-based) primer sets differ (lib/nextera.py). *Why:* the library must contain the primer-binding sites for every read you want, in the right orientation and spacing; swapping adapter families (TruSeq vs Nextera vs 10x/custom) changes which sequencing primers are needed. *Repo:* lib/seqprimers.py (ROLES = Read 1, Index 1 (i7), Index 2 (i5), Read 2; locates where each primer anneals on a computed final library); lib/illumina.py; lib/nextera.py.
8. **Paired-end turnaround** - after Read 1 (and i7), the cluster's first strand is stripped, the template bridges to the opposite oligo and is resynthesised so the other strand can be primed for the next reads. *Why:* the reason paired-end gives two reads from opposite ends in forward/reverse (FR) orientation; the source of "forward vs reverse-complement i5 workflow". One repo protocol runs Index 2 before turnaround with a custom primer. *Repo:* duplex-pro-seq (custom run recipe including turnaround detail); nextera-mate-pair (RF orientation).
9. **i5 orientation: forward-strand vs reverse-complement workflows** - on MiSeq, HiSeq 2500, NovaSeq 6000 v1.0 reagents, the i5 read is primed by the flow-cell P5 oligo and reads i5 as written in the oligo (forward). On NovaSeq X, NextSeq 500/550/1000/2000, iSeq 100, MiniSeq, HiSeq 3000/4000, NovaSeq 6000 v1.5, a dedicated i5 primer is used and the i5 comes out as its reverse complement. The sample-sheet value therefore differs by instrument, and also by demultiplexing software (bcl2fastq manual sheet vs BCL Convert reading RunInfo.xml orientation flag vs BaseSpace). *Why:* the single most common cause of "all reads undetermined" for new designers; a library design (and the index list given to a core facility) must state which orientation it assumes. The same i7 as in the oligo is the reverse complement of what is read (NEBNext: "the i7 index as carried in the oligo is the reverse complement of the index read"). *Repo:* lib/illumina.py comments; assets/illumina_samplesheet.js (instrument x workflow table: reverseRead set = miniseq, iseq100, nextseq500, nextseq2000, novaseq6000, novaseqx, miseqi100 read-first, hiseq4000); DESIGN.md ("Instrument name alone is insufficient to determine sample-sheet i5 orientation"); scribo-seq page (i5 on NextSeq 500 reverse-complement workflow).
10. **Index reads: length, single vs dual, unique dual (UDI) vs combinatorial (CD)** - 6-, 8-, 10-nt (and longer) indexes; single index, combinatorial dual (i7 x i5 reused), unique dual (each sample has its own pair). The index read length set on the instrument must match the kit (UD 10 bp vs Nextera CD 8 bp). *Why:* index design (pairwise Hamming/edit distance, colour balance, avoiding homopolymers) determines how many samples can be pooled and how robustly misassigned reads are rejected. *Repo:* illumina-dna-prep (10 bp UD vs 8 bp CD; "system must be configured for 10 bp index reads"); truseq-dna-pcr-free and truseq-stranded-mrna (single, CD, UD families); lib/illumina.py NEBNext i501-i516/i701-i724 tables.
11. **Index hopping (index mis-assignment)** - on patterned flow cells with ExAmp, free adapter/primers carried over in the library can prime on already-seeded clusters and swap the index; typical rate ~0.1-2% [KB]. *Why:* mitigation = unique dual indexes, thorough removal of free adapters and primers, no excess index primer in the final pool, and (for critical work) pre-pooled libraries cleaned, not stored long. The pooling of PCR-free libraries or adapter-ligation-only libraries matters most. *Repo:* mentioned in only 2 notes; UDI families appear widely (illumina-dna-prep, truseq).
12. **Custom sequencing primers and custom read structure** - when the read begins with a non-standard handle (barcode on Read 1, custom adapter, barcode inside a transposon), you add your own primer to the cartridge/reagent position (MiSeq: reservoirs 12/13/14 for Read 1, Index, Read 2 custom primers; NextSeq/NovaSeq: dedicated custom-primer positions) at defined concentration, in addition to or instead of the standard primer. *Why:* lets you move barcodes/UMI to the index read or change where the read starts; mismatched Tm or concentration silently gives poor reads; custom i5 needs matching Index 2 primer; ~40+ repo notes. *Repo:* indrop-v1, indrop-v2, atrandi-wgs, cage, cagescan, s3-atac, snubar-atac, sci-car-seq, scifi-atac-seq, hydrop-rna, dscatac-seq, spear-atac, crispr-sciatac, seq-well-s3, safe-seqs/saferseqs, smmip, strand-seq, ntt-seq, light-seq, tcr-map, surecell-3-wta-for-ddseq, earth-microbiome-project-its (MiSeq custom primers 12/13/14, 151x12x151 cycles). lib/seqprimers.py custom().
13. **Dark cycles** - cycles run without imaging (chemistry only) so a fixed or uninformative stretch (linker, constant sequence, long barcode connector) is skipped without costing data or cluster-calling resources; set via cycle/run-parameter changes. *Why:* lets a read start at the informative part (e.g., sci-ATAC, CH-ATAC, multiome-ATAC: dark windows inside barcode-bearing reads) and avoids imaging low-diversity constant sequence. Increases consumed cycles. *Repo:* sci-atac-seq, sciplex-atac-seq, ch-atac-seq (dark windows 11-33, 44-62), snatac-seq, txci-atac-seq, sci-atac-seq3, 10x-chromium-single-cell-multiome, phospho-seq, chymera, drop-scchip-seq, drop-chip, illumina-16s (custom run), guide-seq, gam, cpt-seq, itchip-seq. Note: no structured model of dark cycles in the repo's SequencingPlan; they appear as text.
14. **Base diversity / low-diversity libraries and PhiX spike-in** - cluster identification (older instruments, first ~4-5 cycles) and per-cycle colour calibration need balanced base composition at each cycle; amplicons, restriction-site-start libraries, shared barcodes, bisulfite, CRISPR guide libraries have identical or skewed bases at the start of reads. PhiX (balanced genome, with its own control run function) is spiked at 1-5% normally and 10-30% for low diversity. Offsets/staggered primers and 5' N-padding are alternatives. *Why:* a design with constant first bases fails without PhiX or staggering. *Repo:* illumina-16s (recommends 15-30% PhiX, the EMP-ITS note 5-10%); ~49 notes mention PhiX (10% for one plate-pool run; 1% as control lane); sci-/amplicon protocols.
15. **Phasing and prephasing** - a growing fraction of molecules in a cluster get ahead or behind by one base, so signal purity decays with cycle number and quality drops toward the read end (especially Read 2 and long reads). *Why:* sets practical read length, and low-complexity/homopolymer regions suffer more; extra-long Read 1 handles (e.g. 28-base barcode+UMI + long inserts) must still read cleanly. *Repo:* implicit in read-length choices; not modelled.
16. **Insert size, read length, adapter read-through** - insert shorter than read length makes the read run into the adapter (TRIM_SEEN_IN_READ1/2 in lib/illumina.py); insert shorter than 2 x read length produces overlapping mates; bridge/ExAmp amplification efficiency falls off above ~700-1000 bp; typical NovaSeq inserts 300-500 bp. Cycle-kit size (e.g. 300-cycle = 2 x 150 + indexes). *Why:* pick the fragment-size distribution (size selection, fragmentation time) to the read length; trim adapters in analysis; amplicons (16S V3-V4) need long reads and merging. *Repo:* lib/illumina.py (NEBNEXT_FS_SIZING: fragmentation minutes to bp range); illumina-dna-prep (250-1000 bp, ~600 bp mean); nextera-mate-pair; illumina-16s.
17. **Mate-pair / outward-facing orientation** - Read 1 and Read 2 may point outward (RF) when the library is a circularised, junction-captured long molecule. *Why:* analysis must know orientation to interpret pair distances; design must preserve the junction. *Repo:* nextera-mate-pair; Hi-C style protocols.
18. **Illumina "Y-adapter"/forked adapter structure and the P5/P7 + index + read-primer building block** - a full PCR oligo is P5 + [i5] + Read1-primer-site / P7 + [i7] + Read2-primer-site; adapters ligated (TruSeq, forked, dA/dT overhang, 12-bp duplex STEM) vs installed by PCR (Nextera, 16S two-step) vs transposase (tagmentation). *Why:* these three installation routes determine where the index sits and whether indexing is by ligation (index inside adapter) or PCR (index in primer), and how many cycles are needed to complete truncated adapters (NEBNext: min 3 PCR cycles). *Repo:* lib/illumina.py (TRUSEQ_P5_FULL, NEBNEXT_HAIRPIN, NEBNEXT_I5/I7 sets); truseq-dna-pcr-free, truseq-stranded-mrna, nextera-xt, illumina-dna-prep, illumina-16s-metagenomic-sequencing.
19. **Tn5 tagmentation specifics: mosaic end, 9-bp gap, S5/S7 entry points** - the 19-bp mosaic end sits next to the insert and is read through when insert is short; the 9-bp gap is filled at 72 C before the first denaturation. *Why:* you can see ME_RC in reads as the adapter to trim; the transposon end sequence is fixed so Read 1 starts with ME in some designs. *Repo:* lib/nextera.py; nextera-xt-dna-library-prep, illumina-dna-prep (bead-linked tagmentation), atac-seq, 10x-chromium-single-cell-atac, Smart-seq3.
20. **Index position inside the read vs separate index read** - sample/cell indexes can be read as Index 1/Index 2 (cheap, clean) or embedded in Read 1/Read 2 (needs demultiplexing inside the FASTQ). 10x scATAC places the 16-nt cell barcode in the i5 position. *Why:* dictates cycle counts, primers, and what FASTQ files you get (R1/R2/I1/I2). *Repo:* 10x-chromium-single-cell-atac (barcode in i5), sci-ATAC-seq, dsciATAC, scribo-seq (i5 10 nt cell index on NextSeq 500 with bcl2fastq mask Y*,I*,Y*).
21. **Optical vs clustering duplicates; unique molecular identifiers (UMIs)** - duplicates on patterned flow cells arise from nearby wells (optical) or from the clonal amplification itself (clustering/ExAmp); neither is PCR duplication. UMIs placed in adapters or RT primers count original molecules. *Why:* UMI length and position (R1 vs R2 vs index read) must be planned with the cycle budget; UMIs tolerate sequencing but not index-hopping-level swaps. *Repo:* ~357 notes mention UMIs; 10x v3 reads (28/8/0/91), NEB UMI adaptor (lib/illumina.py: proprietary), smart-seq3.
22. **Nanowell loading conditions and instrument-specific constraints (e.g. exclusion amplification needs adequate loading)** - [KB, minor] ExAmp on patterned flow cells is sensitive to library size distribution and over-short or over-long fragments. *Why:* a bimodal library will be dominated by short fragments.

## B. DNBSEQ / MGI

23. **Circularisation of the library** - after adapters are added, the library is denatured, a splint oligo hybridises across the two ends, ligase closes a single-stranded circle (ssCir); linear leftovers are digested with an exonuclease. MGI's dual-barcode circularisation kit takes only MGI UMI/UDB adapter PCR products, and is not suitable for single-barcode libraries. *Why:* only adapters compatible with MGI's splint work; Illumina libraries need a conversion step (or MGI-specific PCR primers); yield and QC are by ssDNA Qubit (>= 80 fmol in the vendor manual). *Repo:* dnbseq-library-circularization (01_dnbseq.md; manual 7.0 numbers); adapter set is "MGI Dual Barcode Adapter & Barcode Sequences" (separate from Illumina). Unresolved in repo: which strand is circularised, splint bases, platform sequencing primers.
24. **DNA nanoballs (DNB) by rolling-circle replication** - phi29 copies each circle into a long single-stranded concatemer (many tandem copies) that collapses into a ~200-300 nm ball loaded onto a patterned array. *Why:* the amplification is copy-number only from one molecule, so no PCR errors accumulate in clusters, and there is no bridge/ExAmp swapping, which gives low index hopping; library must be circularisable. *Repo:* dnbseq-library-circularization; DNBSEQ mentioned in about 9 notes (microwell-seq, simple-seq, spatac-seq, uda-seq, fipresci, sureselect-xt-hs2, pt-seq-platinum, eccdna-circle-seq).
25. **cPAS (combinatorial probe-anchor synthesis) readout** - anchor primer plus fluorescent probes read short stretches in successive cycles, not per-base terminators. Reads are shorter on some models (SE/PE 50-150). [KB] *Why:* different error profile (substitutions, lower duplicate/chimera rate) and different adapter and primer design; barcodes are read as an extra read.
26. **Platform-specific adapters and barcodes** - MGI adapters differ from Illumina TruSeq/Nextera; Illumina-style libraries can be converted with MGI's universal conversion kit. *Why:* the primers and read structure designed for Illumina don't transfer. *Repo:* dnbseq (adapter "trimming arms" printed in MGI document).

## C. Element AVITI (little in the repo)

27. **Sequencing by avidity, polonies on a surface** - library circularised (or adapter-converted), rolling-circle amplified into polonies on a flow cell, read with multivalent fluorescent avidite probes binding cognate bases; non-terminated chemistry [KB]. *Why:* libraries made for Illumina often convert with an adapter step; low index hopping and flexible read lengths (PE150, up to 2 x 300 on cloudbreak chemistries) [KB]; custom-primer/index rules differ. *Repo:* mentioned in about 4 notes: phospho-seq (multi-assay read lengths for AVITI vs Illumina), sum-seq, atrandi-wgs (Nextera-tailed route to Element AVITI PE150), g4rp-seq. No protocol directory.

## D. Ultima Genomics (little in the repo)

28. **Open-wafer, flow-based SBS with unterminated nucleotides** - clonal beads (emulsion amplification) on a spinning wafer; one nucleotide type is flowed at a time with unterminated dNTPs and the signal strength gives homopolymer length (flow-space read) [KB]. *Why:* single-end reads with in-read indexes, homopolymer-length-dependent errors, cheaper per base but different adapter/library specification (Ultima adapters, UG conversion). *Repo:* only about 2 mentions; no protocol directory.

## E. PacBio HiFi (SMRT)

29. **ZMW and real-time single-molecule sequencing** - a polymerase immobilised in a zero-mode waveguide incorporates phospholinked fluorescent nucleotides; pulses are recorded in real time. Library molecules are loaded by diffusion (size-biased towards short molecules). [KB] *Why:* library size distribution controls loading and yield; short fragments and adapter-dimers outcompete long inserts.
30. **SMRTbell topology** - double-stranded insert closed at both ends with hairpin adapters, so a covalently closed circular single strand. The sequencing primer anneals to the hairpin; polymerase (strand-displacing) travels around repeatedly. Repo models it as a "dumbbell invariant: top insert, right hairpin, reverse-complement insert, left hairpin". *Why:* the library has to be a closed circle with dA/T-tail-ligated hairpins; open ends or nicks reduce sequenceable molecules, which is why nuclease treatment of unligated molecules is in the prep. *Repo:* pacbio-smrtbell-prep-kit-3-0, pacbio-smrtbell-express-template-prep-kit-2-0, pacbio-isoseq-smrtbell-prep-kit-3-0.
31. **Subreads, CCS and HiFi** - the same insert is read multiple passes; subreads are collapsed into circular consensus (CCS); HiFi = CCS >= Q20 (typically Q30+). Insert size 10-25 kb trades passes against length. [KB] *Why:* with 15-20 kb insert WGS the WGS shearing target (15-20 kb), size selection (35% AMPure PB 3.1X) is part of the protocol; too long means fewer passes and lower accuracy. *Repo:* pacbio-smrtbell-prep-kit-3-0 ("recommends shearing to 15-20 kb"; polymerase path "forward and reverse-complement passes").
32. **Polymerase kinetics (IPD and pulse width) for base modifications** - modified bases (5mC, 6mA, and some others) alter polymerase kinetics and can be called from HiFi data. *Why:* PCR-free libraries preserve the native signal; PCR erases it. *Repo:* 5hmc-chemical-label-smrt-sequencing (chemical labelling for SMRT detection); [KB] kinetic methylation calling.
33. **Barcoded adapters/primers and Iso-Seq / Kinnex concatenation** - full-length cDNA with barcoded primers (bc01-12), then segments joined into long arrays (MAS-Seq adapters, Kinnex primer mixes A-G/HQ) so one HiFi read contains many transcripts, segmented computationally; a kit-specific sequencing primer is annealed. *Why:* library design can raise throughput by making reads longer rather than more; barcodes inside the molecule are found after trimming, and artifact-free joining matters. *Repo:* pacbio-kinnex-full-length-rna; pacbio-isoseq-smrtbell-prep-kit-3-0; pacbio-telobait; cap-seq-long-read-microbiome.
34. **Sequencing primer + polymerase binding step is part of the library prep** - the PacBio standard (or kit-specific) primer anneals to the SMRTbell, then polymerase binds; nothing is added to cartridge afterwards. *Why:* binding-site sequences in the hairpin determine primer choice. *Repo:* pacbio notes ("anneals the Standard sequencing primer before polymerase binding"; Kinnex needs its own primer).
35. **HiFi error profile** - ~99.9% accuracy, errors random indels at low rate; strong for phasing and repeats; sequencing cost per base high. [KB]

## F. Oxford Nanopore Technologies

36. **Nanopore sensing: current signal through a pore while a strand is ratcheted through** - the sequencer reads ionic current (squiggle), not optical signal; there is no sequencing primer. *Why:* nothing like a "read 1 primer" is needed; the only requirement is the motor-loaded adapter at the strand's leading end. *Repo:* lib/nanopore_library.py (motor_sequencing_plan: "a Nanopore library is sequenceable because its leading adapter carries a motor, not because a synthesis primer lands on the construct"; primers=()).
37. **Motor protein, sequencing adapter, and tether** - a helicase/motor on the adapter docks at the pore and meters the strand through; a tether (e.g. Flow Cell Tether, hydrophobic oligo) concentrates library at the membrane. The adapter's motor and bonds are proprietary (the repo marks them as undisclosed role tokens). *Why:* every library must receive an adapter at its end(s); molecules without one are invisible. *Repo:* lib/nanopore_library.py (LA_TOP/LA_BOTTOM ligation adapter, RAPID_ADAPTER, NATIVE_ADAPTER_BOTTOM); oxford-nanopore-ligation-sequencing-v14 (priming with Flow Cell Tether).
38. **Ligation kits (LSK114) vs rapid kits (RAD114) vs ultra-long (ULK114)** - ligation: end-repair, dA-tail, ligate motor adapter (long reads, good yield, higher input); rapid: transposase fragments the DNA and attaches adapter in one step (minutes, low input, but read length set by transposase cutting and no end-prep); ultra-long: gentle extraction, then limited transposition to target N50 > 50 kb. *Why:* trade-off between time, input, length, and yield; transposase libraries are not blunt-end ligation-compatible. *Repo:* oxford-nanopore-ligation-sequencing-v14, oxford-nanopore-rapid-sequencing-v14, oxford-nanopore-ultra-long-v14.
39. **Native barcoding and PCR barcoding** - barcodes ligated (dT-tailed barcode adapter, then pooled, then motor Native Adapter ligated) or added by PCR; native route is PCR-free and keeps base modifications. *Why:* choose by whether modification calls matter and by input. *Repo:* oxford-nanopore-native-barcoding-v14; oxford-nanopore-cdna-pcr-sequencing-v14.
40. **cDNA sequencing (PCR-cDNA, direct cDNA) and direct RNA (RNA004)** - cDNA: template-switch RT with an adapter handle (SSPII with UMI in the repo: TTVVVV... ) and PCR or no PCR; direct RNA: RNA ligated to an RT adapter (RTA) for structural support, RNA is the sequenced molecule and passes the pore 3' to 5', then RNA ligation adapter (RLA) with motor. *Why:* direct RNA retains modifications (m6A etc.) and polyA length but demands high-quality RNA, and reads begin at the 3' end; cDNA gives transcript strand handled by design. *Repo:* oxford-nanopore-direct-rna-sequencing-rna004, oxford-nanopore-direct-cdna-sequencing, oxford-nanopore-cdna-pcr-sequencing-v14, lib/nanopore_library.py (RTP, CRTA, SSPII_*).
41. **Strand direction and adapter ends: which end enters first** - the end carrying the motor enters first, so design determines which end of the insert is read first (and the leading end gets worse quality at the end of reads). *Why:* targeted designs (Cas9 cut, adaptive sampling) rely on adapter attachment at a specific end. *Repo:* nanopore-cas9-targeted-sequencing-ncats, catch-nanopore; nanopore library `single_strand_rows("pore-entry strand")`.
42. **Basecalling and modification calling** - neural-network basecallers (Dorado; fast/hac/sup models) convert signal to bases with Phred-like qualities; modified bases (5mC, 5hmC, 6mA, m6A) can be called from the same signal; models are chemistry- (kit/pore) specific and retrained. Simplex vs duplex (template + complement read in tandem gives higher accuracy). [KB] *Why:* raw-signal retention (POD5), kit and flow-cell version and basecaller version must be recorded; native libraries (no PCR) are required for modification calling.
43. **Read length is the molecule length; yield depends on molarity** - reads are the entire fragment (no length limit from cycles); yield and pore occupancy are set by molar amount of adapter-bearing ends, so shearing or damage drops sequenced length. *Why:* ONT inputs are specified in fmol; adapter-ligation efficiency and short fragment contamination are important quality factors. [KB]
44. **Nanopore error profile** - ~1-5% historically, now Q20+ with modern chemistry; errors are indels in homopolymers and some methylation-context-dependent errors. [KB]
45. **Real-time selection and run control (adaptive sampling)** - can reject molecules mid-read to enrich or deplete targets without library prep changes. [KB] *Why:* a design may use software instead of capture; library needs long, native molecules.

## G. Sanger sequencing (baseline)

46. **Dideoxy chain termination with a single primer on one clonal template** - each reaction yields fluorescently labelled terminated fragments separated by capillary electrophoresis; a base per peak in a chromatogram; read length 700-1000 nt, per-base Phred scores originated here. [KB] *Why:* the conceptual baseline (one primer, one template, read direction fixed); still the validation of constructs (clones, edits, guide cuts) and must be clonal, so mixed products give overlapping peaks. *Repo:* many notes use Sanger as validation (e.g. UGI-gRNA association by Sanger in a CRISPR protocol; bisulfite Sanger validation separate from library route).
47. **Contrast table to teach** - Sanger: 1 template/reaction, no library; NGS: massive parallel, requires universal ends so any fragment can be amplified/read; consequences for pooling and indexing. [KB]

## H. Generic concepts

48. **Read structure notation** - written as cycles per read, e.g. 28/8/0/91 (10x GEX v3: R1 28 = 16 nt barcode + 12 nt UMI, I1 8 = sample index, I2 0, R2 91 = cDNA), or BCL Convert OverrideCycles (Y = read, I = index, U = UMI, N = skip), bcl2fastq use-bases-mask (e.g. Y*,I*,Y*). Dark cycles can be written as N. *Why:* the library designer fills the read structure; mismatch with run setup is a top failure mode. *Repo:* lib/seqprimers.py (read_spec, read_spec_table, FeatureReadSpan: first bases each read reports); 10x pages (28/8/91); scribo-seq (Read 1 75, i7 6, i5 10).
49. **FASTQ format** - 4 lines per read: name, sequence, "+", per-base quality; Illumina emits per-lane/per-read files R1/R2 (and I1/I2 when kept); name carries flow-cell lane, tile, coordinates, read number, and barcode. *Why:* what the analysis sees; single-cell designs require I1/I2 or barcode-in-read outputs to be retained (the repo notes intensity files and index FASTQs retained). 
50. **Phred quality scores** - Q = -10 log10(P_error); Q20 = 1%, Q30 = 0.1%; Phred+33 ASCII; NovaSeq/NextSeq 2000 bin qualities into a few levels; per-platform calibration differs (HiFi from consensus, ONT from model). *Why:* filter, trim, compare across platforms; quality drops with cycle number (Illumina) or at read ends (ONT).
51. **Demultiplexing and barcode error handling** - assign reads to samples by index (bcl2fastq, BCL Convert); allowed mismatches (typically 1 for edit distance >= 3 between barcodes); index collision rule; "Undetermined" file; for ONT, the basecaller (Dorado) demultiplexes by barcode adapter. *Why:* barcode set design (distance, uniqueness, balance), index length, i5 orientation, and sample sheet all interact. *Repo:* assets/illumina_samplesheet.js; DESIGN.md sample-sheet export; lib/illumina.py index tables.
52. **What goes into R1/R2/I1/I2 for single-cell designs** - typical patterns: (a) 3' GEX (10x v3, Drop-seq, inDrops): R1 = cell barcode + UMI (some with custom primer), R2 = cDNA, I1 = sample, I2 = none. (b) 5'/Smart-seq3-like: UMI in R1 5' tag with R2 cDNA. (c) scATAC (10x): R1/R2 = genomic ends, I1 = sample, I2 = cell barcode (16 nt). (d) sci-/combinatorial indexing: barcodes in both Tn5 and PCR indexes read as I1/I2 or inline. (e) feature barcoding / CRISPR / CITE-seq: R1 cell barcode+UMI, R2 feature barcode. (f) 10x multiome, as recorded in one repo note: ATAC Read 1 55 / Index 1 11 / Index 2 16 / Read 2 55; RNA Read 1 95 / Index 1 6 / Index 2 16 / Read 2 21. *Why:* the combined structure is determined by where each element is placed during library prep; read order and length budget; platform (Aviti 79/11/16/79 in one note) alters allowed lengths. *Repo:* 10x-chromium-single-cell-3-ge-v3 (28/8/91), 10x-chromium-single-cell-atac, 10x-multiome, drop-seq, indrop-v1/v2 (custom), smart-seq3, bd-rhapsody, sci-atac-seq, s3-atac, hydrop-rna/atac.
53. **Error profiles per platform (comparison table to teach)** - Illumina: low (~0.1-0.5%) mostly substitutions, worse at read ends and Read 2, GC/AT bias in PCR; DNBSEQ: similar, low duplicates; Element: very low (Q40-claimed); Ultima: homopolymer length errors; PacBio HiFi: ~Q30+ after consensus, random indels; ONT: indels and homopolymer errors, improving with models. [KB] *Why:* determines UMIs/consensus (duplex-pro-seq, safe-seqs, SaferSeqS rely on molecular consensus to beat sequencing error), variant calling, and whether PCR errors or sequencing errors dominate.
54. **Molecular consensus approaches (UMI/duplex sequencing)** - the error-correction concept: sequence each original molecule multiple times with a UMI or duplex barcode; consensus removes sequencing and PCR errors. *Why:* shapes adapter design (random UMI placement; both strands tagged). *Repo:* lib/molecular_consensus.py; safe-seqs, saferseqs, duplex-pro-seq, smmip.
55. **Pooling and loading quantification, and library QC for sequencing** - qPCR for adapter-bearing amplifiable molecules (KAPA), fluorometric + fragment analyser for others; equimolar pooling; denature and dilute; PhiX added at load. *Why:* what the "last step" of every protocol is. *Repo:* truseq-dna-pcr-free, illumina-16s, many notes (Qubit, TapeStation, KAPA qPCR, MiSeq v3 600).
56. **Strandedness and read orientation** - dUTP/USER-based stranded libraries (TruSeq stranded mRNA: polymerase does not copy past dUTP) make R1 antisense or sense; adapters placed by ligation preserve orientation. *Why:* sequencers read whatever strand is clustered; orientation is information only if the library chemistry preserved it. *Repo:* truseq-stranded-mrna; NEBNext hairpin with dU (lib/illumina.py).

## I. Notes on coverage and limits

- The repo has dedicated protocol directories only for Illumina (illumina-dna-prep, truseq-dna-pcr-free, truseq-stranded-mrna, nextera-xt-dna-library-prep, nextera-mate-pair, illumina-16s-metagenomic-sequencing, plus 10x directories), MGI (dnbseq-library-circularization), PacBio (4 dirs), ONT (7 dirs + catch-nanopore, nanopore-cas9...). Element, Ultima, Singular have no directories; mentions are incidental (AVITI 4 notes, Ultima 2).
- Repo's models of sequencing: lib/seqprimers.py (primer landing, reads), lib/protocol_graph.py SequencingPlan (primers + acquired roles + read uses; nanopore has primers=()), lib/nanopore_library.py (motor adapter). Dark cycles, custom-primer reservoir position, PhiX are described in prose but not structured.
- Items tagged [KB] should be verified against current vendor documents before use in teaching material (instrument chemistry details change; e.g., colour counts, read-length limits, accuracy claims).
- Suggested teaching order: Sanger -> SBS basics (read primers, P5/P7, clusters) -> paired-end/index reads/orientation -> custom primers, dark cycles, diversity -> other short-read (DNBSEQ, AVITI, Ultima) -> long-read (PacBio, ONT) -> read structure notation and single-cell designs.
